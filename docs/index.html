Self-hosted voice infrastructure

PipeKit

A low-latency VAD → STT → LLM → TTS pipeline behind an OpenAI Realtime-compatible WebSocket — every model running locally on your own GPU. No provider APIs, no per-minute billing, no audio leaving your VPC. One docker compose up.

View on GitHub Quickstart

What it is

A deployment wrapper around huggingface/speech-to-speech. The pipeline logic lives upstream; PipeKit owns the compose topology, GPU sizing, operational scripts and a pinned upstream commit so redeploys are reproducible. 

                    ┌──────────────────────────────────────────┐
  client ──ws──▶    │ pipekit-core                             │
  (OpenAI Realtime) │  Silero VAD → Parakeet TDT → LLM → Qwen3 │
                    └───────────────────┬──────────────────────┘
                                        │ http (OpenAI-compatible)
                    ┌───────────────────▼──────────────────────┐
                    │ llm-engine — llama.cpp server-cuda       │
                    └──────────────────────────────────────────┘
                              both share GPU 0

Drop-in protocol

Standard OpenAI Realtime client SDKs work — just repoint the base URL. No custom socket code.

Fully local

STT, LLM and TTS weights all sit on your GPU. Audio never leaves the instance.

Barge-in included

VAD-driven interruption cancels the in-flight response mid-sentence, as the protocol expects.

Stack

Every stage is a flag away from being swapped.

StageComponentWhy
VADSilero VAD v5turn-taking and speech boundaries

Quickstart

Launch a GPU instance from the Ubuntu Deep Learning AMI — it ships the NVIDIA driver, CUDA runtime and container toolkit already configured. Give it ~60 GB of EBS. 

git clone https://github.com/sauravtom/pipekit && cd pipekit
cp .env.example .env    # set HF_TOKEN
./scripts/bootstrap-ec2.sh
docker compose up -d

bootstrap-ec2.sh is read-only by default: it checks driver, VRAM tier, Docker, Compose v2, GPU passthrough and disk. First boot downloads the GGUF plus STT/TTS weights into ./cache/ — expect 10–20 minutes. Then watch for: 

OpenAI Realtime API starting on ws://0.0.0.0:8765/v1/realtime (pool size 1)

Verify it

pip install websockets
make smoke HOST=<ec2-ip>                     # session opens?
make smoke HOST=<ec2-ip> AUDIO=hello.wav     # full turn + time-to-first-audio

Sizing the GPU

STT, LLM and TTS weights co-reside, so VRAM is the binding constraint.

InstanceGPUVRAMSettings
g5.xlargeA10G24 GBdefaults as shipped (LLM_CTX=32768)
g4dn.xlargeT416 GBLLM_CTX=8192, NUM_PIPELINES=1, consider dropping --swa-full

NUM_PIPELINES caps concurrent sessions; each pipeline holds its own STT/TTS handlers. Connections beyond the pool size are rejected with session_limit_reached rather than queued.

Consuming the API

ws://<host>:8765/v1/realtime speaks the OpenAI Realtime protocol.

from openai import AsyncOpenAI

client = AsyncOpenAI(base_url="http://<ec2-ip>:8765/v1", api_key="unused")

async with client.realtime.connect(model="local") as conn:
    await conn.input_audio_buffer.append(audio=b64_pcm16)   # 16 kHz mono
    async for event in conn:
        if event.type == "response.output_audio.delta":
            play(event.delta)

Audio in and out is PCM16 at 16 kHz by default — the pipeline's native rate. The server resamples if you declare another rate via session.update. Operational endpoints ride the same port: GET /v1/pool for per-unit occupancy, GET /v1/usage for aggregate counters.

Leaner transport: raw PCM

Skip the protocol entirely — no JSON envelope, no interruption events, no live transcripts. Stream 16 kHz int16 mono PCM in, get audio bytes out. 

docker compose -f docker-compose.yml -f docker-compose.raw-pcm.yml up -d

No authentication. Anyone who can reach port 8765 can use your GPU. Don't put it on 0.0.0.0 in a public subnet — restrict the security group to known CIDRs, front it with an ALB or nginx terminating TLS and checking a bearer token, or keep the port private behind a VPN.
